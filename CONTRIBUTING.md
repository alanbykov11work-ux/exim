# Порядок работы

## 1. Загрузка существующего приложения

Сейчас репозиторий содержит только координационный каркас. Интегратор должен загрузить сюда существующий локальный код именно того приложения, которое развёрнуто как EXIM Super App.

Обязательно сохранить:

- реальную структуру и текущий стек;
- package/manifests и lock-файлы;
- migrations/schema;
- тесты и штатные команды;
- deployment-конфигурацию без секретов;
- Git-историю, если она уже существует.

Не загружать `.env`, credentials, private keys, дампы production-базы, cookies и реальные персональные данные.

Импорт выполняется отдельной веткой `import/application-baseline` и Pull Request в `main`. Не перезаписывать координационные файлы молча: при конфликте сохранить правила безопасности и объяснить изменение в PR.

## 2. Фиксация baseline

После merge исходного кода Codex/куратор:

1. проверяет origin, стек, историю и отсутствие секретов;
2. подтверждает штатные команды и Vercel/Supabase linkage по фактам репозитория;
3. записывает exact `main` SHA и test/Preview target в `docs/ai-workflow/current-task.md`;
4. переводит задачу из `awaiting_application_source` в `ready`.

После этого Claude начинает реализацию без дополнительного разрешения.

## 3. Реализация и приёмка

`ready → in_progress → submitted → in_review → ready_for_acceptance → accepted`

Если нужны исправления:

`in_review → changes_requested → in_progress → submitted`

Blocker не скрывается: он оформляется отдельным файлом и возвращается в работу только после устранения причины.
