# Рабочий цикл Claude Code ↔ Codex

Цель — выпускать проверяемые изменения и сохранять результаты в репозитории.

## Разрешение публикации

С 2026-11-16 действует [deployment-policy.md](deployment-policy.md). Claude/интегратор могут исправлять и публиковать существующий Super App, включая production и необходимый merge, без нового разрешения Codex. Прежняя последовательность «сдача → ждать reviewer → получить следующий сигнал» не является обязательным стоп-шагом публикации.

## Источники и роли

- Владелец задаёт продуктовую цель и финальную приёмку.
- Product OS задаёт бизнес-правила; pinned commit сохраняется read-only.
- Приложение и manifests/config/migrations задают фактический стек/состояние.
- current-task.md задаёт текущую работу, deployment-policy.md — действующее разрешение выпуска.
- Claude/интегратор реализуют и публикуют; Codex может независимо проверять, но его отдельное одобрение не является дополнительным обязательным условием.
- Исполнитель не выдаёт себя за независимого reviewer и не объявляет собственную работу принятой владельцем.

## Рабочий ритм

Проверить target и локальные изменения → выполнить безопасный срез → проверить → push/PR → публиковать по safety gates → проверить живой результат → сообщить URL/SHA и остаточные проблемы → продолжать доступную работу.

Не ждать ready, следующую волну или полный комплект документов ради безопасной технической подготовки. Отсутствующая тестовая среда блокирует зависящую от неё проверку, а не всю работу. Реальные security/data blockers не скрывать.

## Отчётность

Статусы отражают факты, не заменяют доступ и не требуют церемонии для продолжения. Сохранять историю и exact code/deployment SHA. Старые submission/blocker/evidence/addendum append-only; новые результаты добавлять следующим номером. Краткий понятный результат в PR обязателен после существенного среза; подробную AC-матрицу дополнять по мере проверки, не выдавая NOT_RUN за PASS.
