# Рабочий цикл Claude Code ↔ Codex

Цель этой папки — сделать передачу задач и результатов проверяемой и не зависящей от истории чатов.

## Роли

- Владелец продукта утверждает продуктовые решения и финальную приёмку.
- Task curator/Codex фиксирует current task, baseline и scope, проверяет отчёт и готовит следующую задачу.
- Интегратор + Claude Code реализуют только current task и предоставляют доказательства.
- Reviewer не должен быть тем же агентом, который писал реализацию.

## Канонические источники

- Product OS: требования и продуктовые решения.
- Этот Git-репозиторий: фактический код и техническая реализация.
- `current-task.md`: текущий разрешённый этап и точные идентификаторы.
- Pull Request + reports: фактическая сдача конкретного commit.

## Один полный цикл

1. Codex фиксирует task, Product OS ref, application baseline, target environment и acceptance criteria.
2. Claude выполняет preflight. При несовпадении пишет blocker до изменений.
3. Claude работает в task-ветке и открывает application PR.
4. Claude добавляет submission и evidence manifest для exact commit.
5. Codex независимо проверяет diff, тесты, Preview, роли, tenant isolation и каждый AC.
6. При ошибках создаётся `review-NN.md` с `changes_requested`; старые отчёты не переписываются.
7. После успешного review владелец принимает или отклоняет результат.
8. Только после терминального решения Codex делает следующую задачу текущей.

## Статус и writer

Канонический статус задачи меняет только task curator. Исполнитель в PR лишь запрашивает переход. `submitted` наступает после публикации проверяемого application PR и полного отчёта, а не после локальной фразы «готово».

## Append-only отчёты

После публикации `submission-NN`, `blocker-NN` и соответствующий manifest не изменяются и не удаляются. Исправление получает следующий номер. Это сохраняет честную историю работы и ошибок.
