# TASK-2026-001 — Wave 1 migration plan

## Что добавляет миграция

`supabase/foundation_wave_1.sql` добавляет изолированный tenant-контур без изменения существующих бизнес-данных:

- organizations и tenant workspaces;
- client companies;
- многоролевые memberships;
- инертные organization capabilities;
- module entitlements;
- tenant audit;
- RLS и проверяемые server-side access helpers.

Миграция не создаёт реальные аккаунты, не угадывает компанию по email и не переносит существующие `orders`, `transports`, CRM, tasks или chats в новый scope.

## Безопасное применение

1. Только отдельный Supabase test/Preview project.
2. Зафиксировать backup и текущий schema dump.
3. Выполнить `supabase/foundation_wave_1.sql` одной транзакцией.
4. Создать только синтетические Workspace A/B, A1/A2/B1 и семь тестовых accounts.
5. Проверить RLS отдельными сессиями каждого account и прямыми REST-запросами.
6. Не подключать legacy private objects к tenant scope, пока их backfill и rollback не доказаны на копии данных.

## Rollback

До загрузки каких-либо данных новые объекты можно удалить в обратном порядке после отдельного подтверждения владельца. После появления memberships или audit events автоматический destructive rollback запрещён: откат выполняется восстановлением test backup либо отдельной reviewed migration. Production rollback в этой task не разрешён.

## Текущий предел проверки

Локально проверяются структура, TypeScript, build и статические security-инварианты. Реальное применение SQL, RLS под семью аккаунтами и миграция legacy objects остаются `BLOCKED`, пока не предоставлен отдельный test Supabase project. Production не используется.
