# TASK-2026-001 — Wave 1c migration plan

## Что добавляет миграция

`supabase/foundation_wave_1c_work_scope.sql` подключает к tenant-контуру CRM, задачи и чаты:
`leads`, `lead_history`, `tasks`, `task_comments`, `chats`, `chat_members`, `chat_messages`.

- `workspace_id` во всех таблицах, кроме `chat_members` (scope берётся из чата); все прежние политики удаляются;
- **CRM** — только менеджер и tenant admin своего workspace; история лидов append-only;
- **задачи** — внутренний инструмент: клиент не создаёт и не читает задачи; исполнитель обязан быть активным сотрудником того же workspace; автор неизменяем; переназначает только автор или менеджер;
- **чаты** — создаются единственной командой `create_chat()`; прямые вставки в `chats` и `chat_members` закрыты, что убирает прежнюю возможность вписать себя в чужой чат по id. Каждый участник обязан состоять в workspace; клиент может начать чат только с сотрудником; чат не смешивает клиентов разных client company. Приостановка membership немедленно закрывает чат для участника;
- `workspace_directory()` — справочник людей: сотрудники видны всем участникам workspace, клиенты — только сотрудникам; email отдаётся сотрудникам и самому пользователю;
- `decide_order()` — решение клиента по предложению как `security invoker`: решают политика и guard Wave 1b, а не функция. Раньше функция вызывалась приложением, но в репозитории отсутствовала;
- колонки `chat_messages.file_path` и `file_name` объявлены в миграции: в живой базе они были добавлены вручную и в репозиторий не попали;
- DELETE не выдаётся ни на одну таблицу; запись блокируется при отключённом entitlement `crm`, `tasks` или `chats`.

## Поведение существующих строк

Fail-closed, как в Wave 1b: лид, задача или чат без `workspace_id` не видны ни одной API-роли. Scope назначает владелец:

```sql
select public.legacy_assign_work_scope('lead' | 'task' | 'chat', '<id>', '<workspace id>', '<причина>');
```

Функция каскадно проставляет scope истории, комментариям или сообщениям, отказывает при повторном вызове и пишет `legacy.work_scope_assigned` в аудит. API-ролям выполнение запрещено.

## Влияние на данные

Строки не удаляются и не переписываются. До backfill существующие лиды, задачи и чаты недоступны через приложение. Участник существующего чата, не состоящий в workspace чата, теряет к нему доступ — это ожидаемое следствие изоляции.

## Безопасное применение

1. Только отдельный Supabase test/Preview project, после backup.
2. Порядок: `crm.sql`, `chats_tasks.sql`, `badges.sql` → `foundation_wave_1.sql` → `foundation_wave_1b_legacy_scope.sql` → `foundation_wave_1c_work_scope.sql`.
3. Включить `crm`, `tasks`, `chats` в `module_entitlements` тестовых workspace.

## Rollback

До backfill — reviewed-миграцией вернуть прежние политики и привилегии и удалить триггеры и функции Wave 1c; nullable-колонки можно оставить. После backfill — восстановление test backup. Откат PR — revert. Production rollback в этой task не разрешён.
