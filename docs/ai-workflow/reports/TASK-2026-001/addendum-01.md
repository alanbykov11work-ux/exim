### Gap: смена роли не пишется в аудит

Ранее в этом отчёте и в комментарии к `admin_roles.sql` утверждалось, что изменения ролей
попадают в аудит. Это неверно: в текущем коде `admin_set_role()` только обновляет
`profiles.role` и никакой записи аудита не делает — таблицы аудита в baseline нет вовсе.
Утверждение убрано. Аудит изменений ролей и критических действий фиксируется как gap
Foundation Gate (REQ-004, AD-003) и в этот cleanup PR не добавляется.

### Ограничение: удаление строк не чистит опубликованную историю

Удаление адресов из текущего файла не удаляет их из уже опубликованной истории Git: три email
остаются доступны в прошлых коммитах публичного репозитория. Этот PR закрывает только текущее
состояние дерева. Изменение видимости репозитория, переписывание истории и любая её очистка —
действия владельца и интегратора, в объём этого PR они не входят и исполнителем не выполняются.

## Организационное ограничение

Интегратор работает с двух компьютеров. Доступ к GitHub сохраняется отдельно на каждом, и
подготовленная ветка физически находится на той машине, где велась работа. Из-за этого между
готовым коммитом и его появлением в GitHub возникает задержка: push выполняет человек.
Практическое следствие — незапушенная работа не считается существующей, поэтому каждый
законченный кусок отправляется в GitHub сразу, а не накапливается локально.
